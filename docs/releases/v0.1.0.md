## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
epoll event loop for Mojo: readiness events, one-shot timers, non-blocking TCP. Callback-free:
`wait()` fills a list you own with `(token, events)` and you dispatch, so there is no closure
storage and no allocation per event. 163 lines of code, libc only, Linux.

Same server CPU per request as uvloop, a third of Python asyncio's, half the memory of either
(echo ping-pong, [docs/perf.md](docs/perf.md)).

```mojo
import aio


def main() raises:
    var lfd = aio.tcp_listen(0)  # 127.0.0.1, a free port
    var loop = aio.Loop()
    loop.add(lfd, aio.IN, 1)
    loop.after(10, 2)  # one TIMER event in 10 ms
    var evs = List[aio.Event]()
    while True:
        _ = loop.wait(evs)
        for ev in evs:
            if ev.events & aio.TIMER:
                print("timer", ev.token, "fired; port", aio.local_port(lfd) > 0)
                aio.close(lfd)
                return
```

## Highlights

- A Mojo network server with uvloop's CPU cost per request and half its memory.
- Timers and sockets in one loop, no callbacks to store.
- Multi-threaded servers: shared epoll set, ONESHOT, per-thread buffers (mojo-bento runs on it).

## Known limits

- Linux x86-64 only (packed 12-byte epoll_event). IPv4 only.
- `wait()` is single-threaded (timer heap); other threads use `ready()`.
- No io_uring; no TLS. CI workflow has not run on GitHub yet (repo not pushed).
